# KORG ELECTRIBE MX — EMX-1 (HLE-эмулятор в одном файле)

Рабочая веб-эмуляция грувбокса Korg Electribe EMX-1: **настоящая фотография панели** как база,
поверх неё — прозрачные интерактивные зоны (ручки, клавиши, пэды, кнопки, LCD), нативный
аудио-движок (Tone.js + резервный WebAudio) и парсер оригинального дампа карты `.BIN` / `.EMX`.

Всё приложение — один файл [`index.html`](index.html). Без сборки и без зависимостей кроме CDN Tone.js.

## Запуск

Открыть `index.html` в браузере (двойным кликом или с любого статического хостинга).
Для iPad: Safari → «Поделиться» → «На экран Домой» — приложение запустится без адресной строки,
панель занимает весь экран. Панель шире экрана, поэтому устройство держится **горизонтально**
(в портретной ориентации появляется подсказка о повороте).

## Как устроена панель

Интерфейс не рисуется «по мотивам» — он наложен на оригинальную фотографию EMX-1:

* база — `#deck.electribe-container` (`position:relative; aspect-ratio:1600/1121; background-repeat:no-repeat`)
  с фотографией панели (2221×1566) в `background-image`; пропорции сохраняются, панель вписывается в окно;
* средний декоративный слой `.hardware-overlay` — лист со всеми кнопками (`image_uBtuLl.png`),
  `width/height: 100%`, `pointer-events: none !important` (картинка кнопок **не** перехватывает тапы),
  `z-index: 2`, то есть строго под интерактивными зонами;
* верхний слой — прозрачные зоны `.touch-pad` (`z-index: 10`) в слоях `#knobs`, `#keys`, `#pads`,
  `#btns`, `#ribbon`, `#lcd`; **все координаты заданы в процентах** от изображения
  (`top/left/width/height`), поэтому геометрия совпадает с фото при любом масштабе — от iPad mini
  до десктопа;
* ручки — круглые зоны захвата ровно над физическими ручками, внутри тонкий белый указатель,
  поворачиваемый `transform: rotate(−140°…+140°)`; управление Pointer Events + `requestAnimationFrame`,
  вертикальное движение пальца = поворот на 190 px полного хода, двойной тап — сброс в центр;
* кнопки (16 шаговых клавиш, DRUM/SYNTH PART, транспорт) в покое полностью прозрачны; при нажатии
  или на текущем шаге включается `.touch-pad.active` — неон «горит изнутри пластика»:
  `background: rgba(255,30,30,.45)`, `mix-blend-mode: color-dodge` (прожигает свет сквозь белые
  кнопки на фото), `box-shadow: inset 0 0 12px #ff0000, inset 0 0 4px #fff` и тонкая красная рамка;
  для SYNTH-партии (бас) используется `.touch-pad.blue-active` — тот же эффект в `#0088ff`;
  бегущий шаг подсвечивается классом `.cur` (белый `outline`, без внешнего размытия);
* LCD — янтарный градиент с чёрным текстом `Courier New` 900 (BPM, паттерн, партия, режим, сетка шагов);
* лампы VALVE FORCE — два слоя в овальном окне фейсплейта: база «выключенные лампы» видна всегда,
  поверх неё `.valve-glow` («горящие») с `opacity: 0` и `transition: opacity .4s`.
  В обработчике PLAY (после `Transport.start()`) слою добавляется класс `.playing`
  → `animation: valvePulse 3s infinite alternate ease-in-out` (opacity .45 → .95);
  в STOP класс снимается, лампы плавно гаснут. Никаких blur-фильтров — только `opacity`;
* светодиоды `.led-indicator` — 8 синих индикаторов микшера (1–8) и три красных FX 1/2/3
  ровно на своих гнёздах: в покое матовые `rgba(40,10,10,.65)` с внутренней тенью (не горят!);
  вспыхивают строго по команде секвенсора — `.led-indicator.active`
  (`background:#ff3333; box-shadow:0 0 8px #ff3333,0 0 15px #ff0000`), синий вариант для микшера
  — `#0088ff`, длительность импульса 80 мс;
* ползунок ARPEGGIATOR (`#ribbon`, слева) — рельефный триггер `#ribKnob` двигается
  `transform: translateY()` на событиях `pointerdown/pointermove` с `setPointerCapture`;
  значение 0.0–1.0 уходит в `AudioEngine.setArp()` → `bassS.detune` (±700 центов) и высота
  арпеджио (пентатоника); в резервном движке — сдвиг частоты осциллятора;
* ручки — `will-change: transform`, поворот `--rot` от −140° до +140°, `pointermove` батчится
  через `requestAnimationFrame`; двойной тап — сброс в центр.

Отладочный режим: `index.html?debug=1` — показывает контуры всех зон поверх фотографии.
Слой кнопок из спрайт-листа можно включить для сравнения: `index.html?sprite=1`.

## Управление

| Элемент | Действие |
|---|---|
| **MASTER VOLUME** | общая громкость |
| **TUBE GAIN / DRIVE** | степень Tube Saturation (драйв) |
| **CUTOFF / RESONANCE** (SYNTH FILTER) | срез и добротность фильтра басовой партии |
| **EG TIME** | спад огибающей баса |
| **FILTER TYPE** LPF/BPF/HPF | тип фильтра (клик по зоне) |
| **DRUM PART 1 / 2 / 3** | выбор дорожек KICK / SNARE / HI-HAT + прослушивание |
| **SYNTH PART 1** | дорожка SYNTH BASS; PART 2–5 — ноты D#2 / F2 / G2 / A#2 |
| **1–16** | программирование шагов выбранной дорожки (красный — нота, белый — бегущий шаг) |
| **PLAY / STOP / REC / ERASE** | транспорт, индикатор записи, очистка партии |
| **TAP TEMPO** | тап-темп (защита от двойных нажатий) |
| **◄ ►** (PATTERN) | переключение паттернов A.01 … D.32 |
| Ribbon (белая полоса) | бас по пентатонике от высоты касания |

На десктопе: `Space` — play/stop, `←/→` — паттерны, `1–4` — дорожки, `Esc` — стоп.

## Аудио

* `Tone.js 14.8.49` с cdnjs; контекст создаётся по первому касанию (`latencyHint: 'interactive'`,
  `lookAhead: 0.02`), чтобы не блокировать запуск и не ломать autoplay-политику Safari.
* Цепочка: партии → `Tone.Distortion` (Tube Saturation) → `Tone.Limiter` → выход.
* KICK — `Tone.MembraneSynth`, SNARE — `Tone.NoiseSynth`, HI-HAT — `Tone.MetalSynth`,
  SYNTH BASS — `Tone.MonoSynth` (sawtooth) → `Tone.Filter`.
* Секвенсор — `Tone.Transport.scheduleRepeat('16n')`, индикация — через `requestAnimationFrame`.
* Если CDN недоступен, автоматически включается компактный резервный WebAudio-движок с тем же API
  (lookahead-планировщик 25 мс) — панель остаётся играбельной офлайн.

## Формат дампа

Дамп карты — 1 831 424 байта, 128 паттернов блоками по **9984** байта, `offset = index * 9984`
(паттерн пересчитывается при выборе в списке, файл повторно не читается):

| Смещение в блоке | Поле | Обработка |
|---|---|---|
| `+0x0000` | BPM, `Uint16` little-endian | `/10` → темп секвенсора и LCD |
| `+0x0040` | KICK, 16 байт | `> 0` → шаг включён |
| `+0x0050` | SNARE, 16 байт | то же |
| `+0x0060` | HI-HAT, 16 байт | то же |
| `+0x0070` | SYNTH BASS, 16 байт | то же |
| `+0x011A` | Cutoff `0–127` | `/127` → ручка CUTOFF + фильтр |
| `+0x011B` | Resonance `0–127` | `/127` → ручка RESONANCE + `Q` |

Файл читается `FileReader.readAsArrayBuffer`, поддерживается drag & drop на окно.
После загрузки дампа `state.isDemoMode → false`, индикатор `<div class="badge warn">DEMO</div>`
в нижней панели гаснет и заменяется зелёным `LIVE / ORIGINAL DATA`; на LCD в режиме ожидания
вместо `STOP` пишется `DEMO`, пока дамп не загружен. Все 16 шаговых клавиш работают всегда —
и в демо, и на оригинальных данных.
Выбор паттерна (`A.01…D.32`) вызывает `loadPattern()` → переразбор блока, принудительное
обновление стилей (`forceUpdate()`), поворот ручек CUTOFF/RESONANCE на угол из бинарника
и мгновенную установку `filter.frequency.value` / `filter.Q.value` (без рампы).
Если блок пустой или файл не загружен — играет демо-паттерн (A.01 «SpaceJox» повторяет надпись с фотографии).

## Слой кнопок (спрайт-лист) — почему он выключен по умолчанию

Архитектура из ТЗ реализована полностью: `.electribe-container` + `.hardware-overlay`
(`pointer-events:none !important`) + `.touch-pad` (`z-index:10`). Но лист `image_uBtuLl.png`
**не совпадает** с синей панелью `image__UhWFg.png` ни при каком одиночном преобразовании:

| Проверка | Результат |
|---|---|
| Автокорреляция (FFT, перебор масштаба/сдвига/сдвига по Y) | пик 0.56 |
| Пересечение масок «кнопки ∩ отверстия панели» (перебор 441 вариантов масштаба) | максимум **0.47** (норма ≥ 0.9) |
| Шаг 16 клавиш: панель против спрайта | масштаб 0.943 |
| Тот же ряд у ручек (верхняя строка) | масштаб 0.916 |
| Размер колпачка | спрайт ≈ 1.25× отверстия панели |

То есть горизонтальный масштаб внутри спрайта меняется от строки к строке (0.916 → 0.943) —
это не аффинное преобразование, и одним слоем (`width/height:100%`) лист не ложится никуда:
кнопки уезжают от отверстий до 40 px (~4 % ширины панели), надписи дублируются.
Поэтому по умолчанию базой остаётся фотография реального прибора — она фотореалистична и
геометрия всех зон снята попиксельно с неё. Слой спрайта включён в файл и ставится флагом
`?sprite=1` (или в `?debug=1` — полупрозрачным) для сравнения.
Если нужен именно плоский векторный вид, правильный путь — нарезать лист на 60 отдельных
элементов и расставить их по отверстиям панели (координаты обоих наборов уже измерены,
см. `/tmp/newfit/comps.json`); это отдельная задача, она не требует ручной работы пользователя.

## Производительность

* В покое анимируется только пульсация ламп (`opacity`); шаг секвенсора меняет два класса
  и перерисовывается не чаще одного кадра (`requestAnimationFrame`).
* Ручки двигают одну CSS-переменную `--rot` — без layout-пересчётов и без JS-анимаций.
* Свечение кнопок — `box-shadow` + `mix-blend-mode: screen` на отдельных слоях, без blur-фильтров
  на весь экран.
* Фотография панели вшита в файл (JPEG q80, ~800 КБ base64) — нет запросов к сети, нет FOUC,
  панель появляется вместе с документом.
