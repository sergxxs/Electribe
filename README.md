# KORG ELECTRIBE MX — EMX-1 (HLE-эмулятор в одном файле)

Рабочая веб-эмуляция грувбокса Korg Electribe EMX-1: **настоящая фотография панели** как база,
поверх неё — прозрачные интерактивные зоны (ручки, клавиши, пэды, кнопки, LCD), нативный
аудио-движок (Tone.js + резервный WebAudio) и парсер оригинального дампа карты `.BIN` / `.EMX`.

Всё приложение — один файл [`index.html`](index.html). Без сборки и без зависимостей кроме CDN Tone.js.

## Запуск

Открыть `index.html` в браузере (двойным кликом или с любого статического хостинга).
Для iPad: Safari → «Поделиться» → «На экран Домой» — приложение запустится без адресной строки,
панель занимает весь экран. Панель шире экрана, поэтому устройство держится **горизонтально**
(в портретной ориентации появляется подсказка о повороте).

## Как устроена панель

Интерфейс не рисуется «по мотивам» — он наложен на оригинальную фотографию EMX-1:

* база — `#deck.electribe-container` (`position:relative; aspect-ratio:1600/1121; background-repeat:no-repeat`)
  с фотографией панели (2221×1566) в `background-image`; пропорции сохраняются, панель вписывается в окно;
* средний декоративный слой `.hardware-overlay` — лист со всеми кнопками (`image_uBtuLl.png`),
  `width/height: 100%`, `pointer-events: none !important` (картинка кнопок **не** перехватывает тапы),
  `z-index: 2`, то есть строго под интерактивными зонами;
* верхний слой — прозрачные зоны `.touch-pad` (`z-index: 10`) в слоях `#knobs`, `#keys`, `#pads`,
  `#btns`, `#ribbon`, `#lcd`; **все координаты заданы в процентах** от изображения
  (`top/left/width/height`), поэтому геометрия совпадает с фото при любом масштабе — от iPad mini
  до десктопа;
* ручки — круглые зоны захвата ровно над физическими ручками, внутри тонкий белый указатель,
  поворачиваемый `transform: rotate(−140°…+140°)`; управление Pointer Events + `requestAnimationFrame`,
  вертикальное движение пальца = поворот на 190 px полного хода, двойной тап — сброс в центр;
* кнопки (16 шаговых клавиш, DRUM/SYNTH PART, транспорт) в покое полностью прозрачны; при нажатии
  или на текущем шаге включается `.touch-pad.active` — неон «горит изнутри пластика»:
  `background: rgba(255,30,30,.45)`, `mix-blend-mode: color-dodge` (прожигает свет сквозь белые
  кнопки на фото), `box-shadow: inset 0 0 12px #ff0000, inset 0 0 4px #fff` и тонкая красная рамка;
  для SYNTH-партии (бас) используется `.touch-pad.blue-active` — тот же эффект в `#0088ff`;
  бегущий шаг подсвечивается классом `.cur` (белый `outline`, без внешнего размытия);
* LCD — янтарный градиент с чёрным текстом `Courier New` 900 (BPM, паттерн, партия, режим, сетка шагов);
* лампы VALVE FORCE — два слоя в овальном окне фейсплейта: база «выключенные лампы» видна всегда,
  поверх неё `.valve-glow` («горящие») с `opacity: 0` и `transition: opacity .4s`.
  В обработчике PLAY (после `Transport.start()`) слою добавляется класс `.playing`
  → `animation: valvePulse 3s infinite alternate ease-in-out` (opacity .45 → .95);
  в STOP класс снимается, лампы плавно гаснут. Никаких blur-фильтров — только `opacity`;
* светодиоды `.led-indicator` — 8 синих индикаторов микшера (1–8) и три красных FX 1/2/3
  ровно на своих гнёздах: в покое **полностью прозрачные** (`background:transparent`),
  при запуске не горят вообще; вспыхивают строго по команде секвенсора —
  `.active-red` (`#ff3333`, `box-shadow:0 0 6px #ff3333,0 0 12px #ff0000, inset 0 1px 2px #fff`)
  и `.active-blue` (`#0088ff`, `0 0 6px #0088ff, 0 0 14px #0044ff`),
  длительность импульса 80 мс;
* ползунок ARPEGGIATOR (`#ribbon`, слева) — рельефный триггер `#ribKnob` двигается
  `transform: translateY()` на событиях `pointerdown/pointermove` с `setPointerCapture`;
  значение 0.0–1.0 уходит в `AudioEngine.setArp()` → `bassS.detune` (±700 центов) и высота
  арпеджио (пентатоника); в резервном движке — сдвиг частоты осциллятора;
* ручки — `will-change: transform`, поворот `--rot` от −140° до +140°, `pointermove` батчится
  через `requestAnimationFrame`; двойной тап — сброс в центр.

Отладочный режим: `index.html?debug=1` — показывает контуры всех зон поверх фотографии.
Слой спрайта и нарезанные элементы включаются для сравнения: `index.html?sprite=1`.

## Управление

| Элемент | Действие |
|---|---|
| **MASTER VOLUME** | общая громкость |
| **AUDIO IN THRU / LEVEL** | входящая громкость (трим мастер-шины) |
| **TUBE GAIN / DRIVE** | степень Tube Saturation (драйв) |
| **CUTOFF / RESONANCE** (SYNTH FILTER) | срез и добротность фильтра басовой партии |
| **EG TIME** | спад огибающей баса |
| **FILTER TYPE** LPF/BPF/HPF | тип фильтра (клик по зоне) |
| **DRUM PART 1 … 7B** | 9 ударных дорожек: KICK, SNARE, HI-HAT, TOM, CLAP, RIM SHOT, COWBELL, SHAKER, PERC — пад выбирает дорожку для редактирования и проигрывает её |
| **SYNTH PART 1** | дорожка SYNTH BASS; PART 2–5 — ноты D#2 / F2 / G2 / A#2 |
| **1–16** | программирование шагов выбранной дорожки (красный — нота, белый — бегущий шаг) |
| **PLAY / STOP / REC / ERASE** | транспорт, индикатор записи, очистка партии |
| **TAP TEMPO** | тап-темп (защита от двойных нажатий) |
| **◄ ►** (PATTERN) | переключение паттернов A.01 … D.32 |
| Ribbon (белая полоса) | бас по пентатонике от высоты касания |

На десктопе: `Space` — play/stop, `←/→` — паттерны, `1–4` — дорожки, `Esc` — стоп.

## Навигация (левая секция) и экран

Шесть клавиш режима — **настоящие сенсорные зоны на фотографии панели** (координаты
измерены по исходнику 2221×1566, см. `const NAV`):

| Клавиша | x, y, w, h (пиксели панели) | Меню на LCD |
|---|---|---|
| PATTERN | 221, 846, 112×41 | PATTERN SELECT / LENGTH / GROOVE / SCALE / ROLL / LAST STEP |
| PART EDIT | 352, 846, 113×41 | OSC EDIT / FILTER EDIT / EG EDIT / MOD SETTING / PART LEVEL / PART PAN |
| STEP EDIT | 483, 846, 112×41 | STEP 01/16 / VELOCITY / GATE TIME / MOTION / SHIFT TIMING / TRIG HOLD |
| SONG | 613, 846, 113×41 | SONG 01 NAME / STEP 001 / REPEAT / TRACK / PATTERN / END STEP |
| GLOBAL | 744, 846, 112×41 | **AUDIO OUT** / LCD CONTRAST / KNOB MODE / POWER SAVE / MIDI CLOCK / INIT |
| MIDI | 874, 846, 113×41 | **MIDI CH: 1** / CLOCK / NOTE RX / CONTROL CH / SYSEX / LOCAL |
| CURSOR ▲ | 115, 702, 76×47 | строка меню вверх (на строке SAMPLE — сэмпл назад) |
| CURSOR ▼ | 115, 777, 76×48 | строка меню вниз (на строке SAMPLE — сэмпл вперёд) |

Повторное нажатие закрывает меню, активная клавиша подсвечивается. Внизу экрана есть
дублирующая панель инструментов (все функции, которых на фото нет отдельными зонами, —
`CURSOR ▲/▼`, `EDIT SELECT`, `WAVEFORM`, `MOD TYPE`, `DEST`, `BPM SYNC`, `FILTER TYPE`,
`AMP EG`, `ROLL`, `TAP`, `MUTE`, `SOLO`, `SHIFT`, `KEYS`):

* **CURSOR ▲/▼** — две кнопки стопкой слева под дисплеем (зоны `115,702,76×47` и
  `115,777,76×48` на фото) плюс кнопки `▲ ▼` в нижней панели: перемещение строки внутри
  меню (`state.menuIdx`), на LCD — `n/N`. На строке `SAMPLE` курсор листает варианты
  сэмпла текущей дорожки (`SAMPLE 2/12 BD0009`).
* **TAP TEMPO** — BPM по реальным тапам: усреднение интервалов последних 5 касаний
  (сброс, если пауза > 2.5 с), 4 тапа по 250 мс → 240 BPM.
* **PART MUTE / SOLO** — режим залипает, дальше пад дорожки глушит канал
  (`voice.ch.mute`) или оставляет его солировать (`setSolo`); повторное нажатие SOLO снимает всё.
* **SHIFT + KEYS** — режим клавиатуры: 16 шаговых кнопок играют `C2 … D#3` на басу,
  шаги при этом не переключаются.
* **AUDIO IN THRU / LEVEL** — самая левая верхняя ручка: входной трим мастер-шины.

Светодиоды микшера (синие 1–8) вспыхивают на 80 мс ровно в момент удара сэмпла
(`flashTrack` из колбэка секвенсора), красные FX-индикаторы — для KICK/SNARE/HAT.
Лампы Valve Force при `STOP` имеют `opacity: 0` и плавно разгораются при `PLAY`.

## Аудио

* `Tone.js 14.8.49` с cdnjs; контекст создаётся по первому касанию (`latencyHint: 'interactive'`,
  `lookAhead: 0.02`), чтобы не блокировать запуск и не ломать autoplay-политику Safari.
* **Независимая цепочка на каждый канал.** Все 9 ударных и бас собираются один раз, при старте:

  ```
  Дорожка tr:  Sampler ─→ Tone.Channel(tr) ─┐
                          (pan / volume)    ├─→ masterBus ─→ Distortion(Tube) ─→ Limiter ─→ Out
                          └─→ Gain(send) ─→ fxIn[bus] ─→ FX1|FX2|FX3 ─→ fxReturn ─┘

  FX1 = Tone.Filter (LPF/HPF/BPF/BPF+)      — ручки FX EDIT 1/2: frequency, Q
  FX2 = Tone.PingPongDelay                  — ручки FX EDIT 1/2: delayTime, feedback
  FX3 = Tone.Phaser                         — ручки FX EDIT 1/2: frequency, octaves

  Бас: MonoSynth ─→ bassFilter ─→ Tone.Channel(bass) ─→ lfoTrema(tremolo) ─→ masterBus
       LFO (MODULATION) ─→ lfoAmt.{pitch,cutoff,amp,pan} ─→ цель, выбранная DEST
  ```

  * `EDIT SELECT` переключает `editTarget` (fx1 / fx2 / fx3) — ручки FX EDIT 1/2 правят
    именно выбранный процессор, остальные не трогаются.
  * `FX SELECT` в PART COMMON (и кнопка FILTER на панели, и байт `+0x0120`) направляет
    **текущую** дорожку на FX1 / FX2 / FX3: `voice.send.disconnect() → connect(fxIn[bus])`.
  * `FX SEND` — уровень посыла дорожки (`voice.send.gain`).
  * `ROLL` (зажатие) — `setInterval` по 1/16 или 1/32 (SHIFT+ROLL переключает делитель),
    ретриггерит текущий инструмент, пока палец на кнопке.
  * Ни один узел не создаётся и не удаляется на ходу: только переключение `connect()`.
* Ударные больше **не синтезируются**: ни одного `MembraneSynth`/`NoiseSynth`/`MetalSynth`.
  Один `Tone.Sampler`, в который кладутся `AudioBuffer`. Сэмплы берутся из двух источников:

  1. **Встроенные** (Base64, моно, 22.05 кГц, 16 бит, 0.09–0.45 с, ~108 КБ на все девять) —
     гарантируют звук офлайн, сразу после старта.
  2. **Внешние .wav с GitHub** — при наличии сети пять основных голосов подменяются
     настоящими сэмплами Roland TR-909 (репозиторий `calacuda/1.909`), фоново, без блокировки UI:

     | Дорожка | Файл |
     |---|---|
     | Kick | `samples/BD0.WAV` |
     | Snare | `samples/SN0.WAV` |
     | Hi-Hat | `samples/HH3.WAV` |
     | Clap | `samples/HC0.WAV` |
     | Rim | `samples/RS1.WAV` |

     Загрузка идёт через `fetch` + `decodeAudioData` с таймаутом 8 с: не получилось —
     остаются встроенные сэмплы, приложение не зависит от сети.
     Tom / Cowbell / Shaker / Perc всегда берутся из встроенного набора (в открытых
     архивах подходящих 909-голосов для них нет).
     ⚠️ У репозитория-источника нет лицензии — ссылки используются как внешние URL,
     сами файлы в `index.html` **не** встраиваются; при необходимости замените
     `SAMPLE_URLS` на свой хостинг.
  3. **Internet Archive, коллекция `drum-machines-collection` — импорт ZIP прямо в браузере.**
     Там лежит `Korg Electribe EMX-1.zip` (13 090 393 байта, **207 PCM-сэмплов** — ровно
     столько, сколько в прошивке EMX-1), но **только архивом**: коллекция раздаёт один ZIP
     на аппарат, отдельных `.wav` по прямым ссылкам в ней нет, поэтому URL вида
     `archive.org/download/drum-machines-collection/Korg%20Electribe%20EMX-1/BD.wav`
     не существует. Поэтому ZIP распаковывается на месте:

     ```https://archive.org/download/drum-machines-collection/Korg%20Electribe%20EMX-1.zip```

     * файл кидается в «📂 .BIN / .EMX / .ZIP» (или перетаскивается на страницу);
     * парсится центральный каталог ZIP, `.wav` раскладываются по 9 дорожкам по именам
       (`BD`→kick, `SD`/`SN`→snare, `HH`/`CH`/`OH`→hat, `CP`/`HC`→clap, `RS`→rim, `CB`→cowbell,
       `SH`/`MA`→shaker, `LT`/`MT`/`HT`/`TOM`→tom, `PC`/`PERC`→perc), до 12 вариантов на дорожку;
     * распаковка — нативная `DecompressionStream('deflate-raw')`, а в Safari старше 16.4 —
       встроенный inflate (RFC 1951, ~120 строк, свой, без зависимостей);
     * сэмплы **не** декодируются все сразу: берётся первый вариант каждой дорожки,
       остальные — лениво, когда листаете их курсором;
     * сам ZIP (14.5 МБ) сохраняется в IndexedDB и поднимается при следующем старте
       автоматически, без DEMO и без повторного импорта.

     Проверено в Chromium на ZIP 14.49 МБ / 207 wav: разбор каталога 83 мс,
     9 дорожек подменены, 60.4 FPS при 16 шагах на всех дорожках, ошибок 0.

  | Нота | Дорожка | Сэмпл |
  |---|---|---|
  | `C1` | DRUM 1 | Kick |
  | `D1` | DRUM 2 | Snare |
  | `E1` | DRUM 3 | Hi-Hat |
  | `F1` | DRUM 4 | Tom |
  | `G1` | DRUM 5 | Clap |
  | `A1` | DRUM 6A | Rim shot |
  | `B1` | DRUM 6B | Cowbell |
  | `C2` | DRUM 7A | Shaker |
  | `D2` | DRUM 7B | Perc |

  Шаг секвенсора вызывает `sampler.triggerAttackRelease(note, '8n', time)` — это один
  `BufferSource` на удар вместо десятка осцилляторов, поэтому на A9 нет ни хрипа, ни заиканий.
  Единственный живой синтезатор — `Tone.MonoSynth` для SYNTH BASS.
* Если Tone.js недоступен, резервный WebAudio-движок играет **те же самые** `AudioBuffer`
  через `BufferSourceNode` (без единого осциллятора на ударные) и оставляет осциллятор
  только для баса.
* Секвенсор — `Tone.Transport.scheduleRepeat('16n')`, индикация — через `requestAnimationFrame`.
* Если CDN недоступен, автоматически включается компактный резервный WebAudio-движок с тем же API
  (lookahead-планировщик 25 мс) — панель остаётся играбельной офлайн.

## Маппинг обведённых секций

| Ручка | Куда идёт | Диапазон |
|---|---|---|
| **TUBE GAIN** | `Distortion.distortion` + `wet` | 0…1 |
| **FX EDIT 1** | `Filter.frequency` (FX1) / `Phaser.frequency` / `PingPongDelay.delayTime` | 120 Гц…7.6 кГц / 0.1…9 Гц / 0.06…0.56 с |
| **FX EDIT 2** | `Filter.Q` (FX1) / `Phaser.octaves` / `PingPongDelay.feedback` и `wet` | 0.6…9.6 / 1…5 / 0.15…0.85 |
| **OSC EDIT 1** | `bassS.oscillator.type` | sawtooth → square → triangle |
| **OSC EDIT 2** | `bassS.detune` | 0…100 центов |
| **MOD SPEED** | `lfo.frequency` | 0.1…30 Гц (экспоненциально), при BPM SYNC — `(bpm/60)·(0.25…4)` Гц |
| **MOD DEPTH** | `lfoAmt[d].gain` | cutoff ±2600 Гц / pitch ±600 центов / amp ×0…2 / pan ±1 (DEST: PITCH, CUTOFF, AMP, PAN) |
| **MOD TYPE** | `lfo.type` | sine / sawtooth / triangle / square / random (random — `Tone.Loop('8n')` со случайным значением) |
| **WAVEFORM (MMT)** | алгоритм баса | dual (saw +7 центов) → chord (square −12) → ring (triangle +1200) → waveshape (saw + own detune) |
| **EG INT** | `bassS.filterEnvelope.octaves` / `sustain` | 0…5 октав |
| **PITCH** | `bassS.portamento` | 0…0.25 с |
| **PAN** | `voice.ch.pan` выбранной дорожки (PART COMMON) | −1…+1 |
| **LEVEL** | `voice.ch.volume` выбранной дорожки (PART COMMON) | −40…0 дБ |
| **AUDIO IN LEVEL** | входной трим мастер-шины: `+20·log10(0.5 + ain)` к `masterBus.volume` (×0.5…×1.5) | 0…1 |
| **SAMPLE** (строка PART EDIT) | выбор сэмпла из импортированного ZIP для текущей дорожки | 1…12 |
| **CUTOFF / RESONANCE** | `filterN.frequency` / `filterN.Q` | 55 Гц…10 кГц / 0.4…24 |
| **ARPEGGIATOR (слайдер)** | `bassS.detune` ±700 центов + высота арпеджио | 0…1 |

Все ручки крутятся `--rot` от −140° до +140°, `pointermove` батчится через
`requestAnimationFrame`, `will-change: transform`. Резервный WebAudio-движок повторяет
ту же шину на нативных узлах: `WaveShaper` → `BiquadFilter` → два `DelayNode` с
перекрёстной обратной связью и `StereoPanner` (±1) → четыре `allpass`-биквада с одним
LFO → `DynamicsCompressor`.

## Формат дампа

Дамп карты — 1 831 424 байта, 128 паттернов блоками по **9984** байта, `offset = index * 9984`
(паттерн пересчитывается при выборе в списке, файл повторно не читается):

| Смещение в блоке | Поле | Обработка |
|---|---|---|
| `+0x0000` | BPM, `Uint16` little-endian | `/10` → темп секвенсора и LCD |
| `+0x0040` | DRUM PART 1 — KICK, 16 байт | `> 0` → шаг включён (в дампе значения `0x78`) |
| `+0x0050` | DRUM PART 2 — SNARE, 16 байт | (`0x6e`) |
| `+0x0060` | DRUM PART 3 — HI-HAT, 16 байт | (`0x5a`) |
| `+0x0070` | SYNTH PART 1 — BASS, 16 байт | (`0x3c`) |
| `+0x0080…0x00D0` | PART 4, 5, 6A, 6B, 7A, 7B (TOM, CLAP, RIM, COW, SHAKER, PERC) | шаг `0x10`, тот же формат — **экстраполяция** stride: в предоставленном дампе эти области нулевые |
| `+0x0112` | Pitch / Glide `0–127`, центр 64 | `(v-64)/63` → ручка PITCH/GLIDE + `portamento` |
| `+0x0115` | Pan `0–127`, центр 64 | `(v-64)/63` → ручка PAN + `panner.pan` |
| `+0x011A` | Cutoff `0–127` | `/127` → ручка CUTOFF + `filter.frequency` |
| `+0x011B` | Resonance `0–127` | `/127` → ручка RESONANCE + `filter.Q` |
| `+0x0120` | Тип FX-секции | `% 4` → `OFF / FILTER / DELAY / PHASER`, переключение `wet` |
| `+0x0124` | MOD SPEED | `/127` → `lfo.frequency` 0.1…20 Гц |

Нулевой байт в `+0x0112` / `+0x0115` / `+0x0124` трактуется как «нет данных» и даёт
центральное значение (в предоставленном дампе эти поля пустые, заполнены только
`+0x011A` / `+0x011B`). Янтарный LCD (`Courier New`, `font-weight: 900`) показывает
песню, BPM, паттерн, партию, режим и строку параметров `C70 R30 OFF`
(Cutoff / Resonance / активный FX).

**Что реально лежит в дампе.** Анализ приложенного файла (`1 831 424` байта): ненулевых байт
в нём всего **51**, и все они в блоках **0 (A.01)** и **2 (A.03)** в диапазоне `0x00…0x11B`.
Остальные 126 блоков (A.02, A.04…D.32) полностью пустые — то есть на карте сохранены
только два паттерна. Для пустых блоков приложение подставляет сгенерированный паттерн
(детерминированный `mulberry32` от номера), поэтому все 128 позиций остаются играбельными;
после загрузки настоящего дампа с заполненными паттернами читаются именно они.

Файл читается `FileReader.readAsArrayBuffer`, поддерживается drag & drop на окно.
После загрузки дампа `state.isDemoMode → false`, индикатор `<div class="badge warn">DEMO</div>`
в нижней панели гаснет и заменяется зелёным `LIVE / ORIGINAL DATA`; на LCD в режиме ожидания
вместо `STOP` пишется `DEMO`, пока дамп не загружен. Все 16 шаговых клавиш работают всегда —
и в демо, и на оригинальных данных.
Выбор паттерна (`A.01…D.32`) вызывает `loadPattern()` → переразбор блока, принудительное
обновление стилей (`forceUpdate()`), поворот ручек CUTOFF/RESONANCE на угол из бинарника
и мгновенную установку `filter.frequency.value` / `filter.Q.value` (без рампы).
Если блок пустой или файл не загружен — играет демо-паттерн (A.01 «SpaceJox» повторяет надпись с фотографии).

## Слой кнопок (спрайт-лист) — почему он выключен по умолчанию

Архитектура из ТЗ реализована полностью: `.electribe-container` + `.hardware-overlay`
(`pointer-events:none !important`) + `.touch-pad` (`z-index:10`). Но лист `image_uBtuLl.png`
**не совпадает** с синей панелью `image__UhWFg.png` ни при каком одиночном преобразовании:

| Проверка | Результат |
|---|---|
| Автокорреляция (FFT, перебор масштаба/сдвига/сдвига по Y) | пик 0.56 |
| Пересечение масок «кнопки ∩ отверстия панели» (перебор 441 вариантов масштаба) | максимум **0.47** (норма ≥ 0.9) |
| Шаг 16 клавиш: панель против спрайта | масштаб 0.943 |
| Тот же ряд у ручек (верхняя строка) | масштаб 0.916 |
| Размер колпачка | спрайт ≈ 1.25× отверстия панели |

То есть горизонтальный масштаб внутри спрайта меняется от строки к строке (0.916 → 0.943) —
это не аффинное преобразование, и одним слоем (`width/height:100%`) лист не ложится никуда:
кнопки уезжают от отверстий до 40 px (~4 % ширины панели), надписи дублируются.
Поэтому по умолчанию базой остаётся фотография реального прибора — она фотореалистична и
геометрия всех зон снята попиксельно с неё. Слой спрайта включён в файл и ставится флагом
`?sprite=1` (или в `?debug=1` — полупрозрачным) для сравнения.
### Автоматическая нарезка спрайта (CSS sprite slicing)

Вместо одного листа на весь экран спрайт теперь режется средствами CSS. В коде есть таблица
`SPRITE_SLICES`: для каждого элемента указан прямоугольник-источник в листе
(`sx, sy, sw, sh`, система координат 1536×1024) и прямоугольник-приёмник на панели
(`x, y, w, h`, система координат фотографии 2221×1566). Движок (`buildSprites()` /
`layoutSprites()`) создаёт по `div` на элемент, ставит ему `background-image` — один и тот же
Base64-лист, — а `background-size` и `background-position` считает в пикселях от текущей
ширины панели, поэтому нарезка не «плывёт» при любом масштабе. Пересчёт идёт только в
`layout()` (на `resize`/`orientationchange`), в покое — ноль работы.

Нарезано и выровнено по отверстиям (центры совпали с тач-зонами с точностью 0.0 px):

| Элементы | Источник в листе | Куда ставятся |
|---|---|---|
| 16 шаговых клавиш | `403, 867, 69×81` (эталон из нижнего ряда листа) | 16 позиций `STEP` |
| 9 пэдов DRUM PART | 9 своих прямоугольников из ряда `y≈680` | 9 позиций `DRUM` |
| 5 пэдов SYNTH PART | 5 своих прямоугольников из того же ряда | 5 позиций `SYNTH` |

Пэды нарезаны с сохранением пропорции (лист 70×95 → приёмник 79×107, по вертикали
центрируется в зоне 132 px), поэтому растяжения нет. Ручки намеренно не нарезаются:
у колпачка из листа своя нарисованная риска, она конфликтовала бы с вращающимся
указателем поверх фото. Слой нарезки (`#sprites`) включается флагом `?sprite=1`
(там же, полупрозрачным, показывается и целый лист — для сравнения).

## Постоянное хранение прошивки (без DEMO после перезагрузки)

`localStorage` больше не используется для дампа: строка Base64 на 1.74 МБ (2.44 млн символов)
при старте заметно грузит старую iOS. Вместо неё:

1. При загрузке файла сырой `ArrayBuffer` кладётся в **IndexedDB** (`emx_fw` → store `fw`,
   ключ `dump`) — без кодирования, ровно 1 831 424 байта. Старый ключ
   `localStorage['korg_emx_firmware']` при старте удаляется, чтобы освободить память.
2. В `boot()` сразу вызывается `restoreFirmware()` (чтение IndexedDB), а до его ответа
   показывается встроенный пресет — поэтому DEMO-режима нет ни на одном кадре.
3. После восстановления: `isDemoMode = false`, плашка `LIVE / ORIGINAL DATA` зелёным,
   грузится **A.14**, ручки CUTOFF/RESONANCE разворачиваются из `+0x11A`/`+0x11B`
   и `filter.frequency.value` / `filter.Q.value` ставятся мгновенно.
4. Если файла нет вообще, грузится встроенный в скрипт лёгкий JSON-пресет
   `BUILTIN_PRESET` (A.14 «Deep Floor», 124 BPM, паттерн для всех 10 дорожек),
   плашка — `LIVE / BUILT-IN A.14`. Режима DEMO в приложении больше нет.

## Производительность

* Ударные — это `BufferSource` по одному на удар (сэмплы), а не синтез: исчезает
  постоянная нагрузка на DSP, из-за которой на A9 появлялся хрип.
* В покое анимируется только пульсация ламп (`opacity`); шаг секвенсора меняет два класса
  и перерисовывается не чаще одного кадра (`requestAnimationFrame`).
* Ручки двигают одну CSS-переменную `--rot`, `pointermove` батчится через `requestAnimationFrame`;
  ползунок двигается `transform: translateY`.
* Полный запрет тяжёлого CSS: в файле **ноль** вхождений `mix-blend-mode`, `backdrop-filter`
  и `box-shadow: … inset` (проверено grep). Подсветка активной зоны — плоская полупрозрачная
  заливка `rgba(255,0,0,.5)` + `opacity:.85`; у светодиодов просто плоская заливка
  `#ff3333` / `#0088ff`; у LCD-сетки и указателей ручек тени убраны. Оставшиеся две тени
  (`#deck`, `#tools`) статичны и рисуются один раз.
* Ручки: только `transform: rotate()` + `will-change: transform` (слой композитится,
  без перерисовки), ползунок — `transform: translateY()` + `will-change: transform`.
* Текст LCD пишется только при реальном изменении (`setText()` кеширует последнее значение),
  поэтому шаг секвенсора не дёргает layout лишний раз.
* Замер в Chromium (без GPU), **10 независимых каналов + 3 шины FX + LFO + ROLL**:
  60.3–60.5 FPS при включённых всех 16 шагах на всех дорожках, активном дилее (FX2),
  работающем LFO и зажатом ROLL; худший кадр 25.5 мс, длинных кадров 2–5 за 3 с.
  Ошибок в консоли — ноль, как на Tone.js, так и на резервном WebAudio-движке.
* Никаких `mix-blend-mode` и `box-shadow` в горячем состоянии: `.active` — это плоская
  полупрозрачная заливка + `opacity:.85` + `transform:translateZ(0)`, то есть чистая
  композиция на GPU. А во время перетаскивания ручки или ползунка на `<body>` ставится
  класс `.dragging`, который гасит все переходы, тени и смешивание
  (`transition:none; box-shadow:none; mix-blend-mode:normal`) и ставит на паузу
  пульсацию ламп — этим убирается layout thrashing в мобильном Safari.
* Слой декоративной графики и нарезанные элементы имеют `pointer-events: none !important`,
  все `.touch-pad` — на `z-index: 10`.
* Фотография панели, лист кнопок, лампы и сэмплы вшиты в файл — нет запросов к сети,
  нет FOUC, панель появляется вместе с документом.
